A Student's Guide to Writing and Debugging Code with AI Prompts

Pasting a 60-line traceback with "fix this" teaches you nothing and often introduces subtle regressions. Here is how to structure debugging prompts that pinpoint root causes while keeping your fundamentals sharp.

Computer Science Labs · 7 min read · Prompts & Verification Checklist
AI Code & Debugging Guide

Every computer science student hits the same midnight wall: a pointer arithmetic bug in C, an off-by-one boundary condition in a graph traversal, or an asynchronous React state race that refuses to reproduce consistently. When an assignment deadline is six hours away, pasting the entire source file into an AI chat and copying whatever compiles is tempting—and almost always counterproductive.

Unconstrained code generation often rewrites working helper functions, invents deprecated API flags, or masks the real bug with a try-catch block. Worse, when your midterm asks you to trace the exact same algorithm by hand, borrowed solutions fall apart. High-performing CS students use AI the way senior engineers use a rubber duck paired with a sharp TA: by isolating minimal context, stating their own hypothesis first, and demanding tests rather than blind rewrites.

The Four-Part Debugging Prompt Formula

Whenever your code fails a test case or throws an unexpected compiler error, structure your prompt around four concrete elements before pressing Enter:

  • Environment & Constraints: Specify language version, compiler flags, or disallowed libraries (for example, C11 with -Wall -Wextra, or Python 3.12 without NumPy).
  • Expected vs. Actual Behavior: Show the exact failing input, what your function should return, and the exact terminal output or stack trace.
  • Minimal Reproducible Snippet: Trim unrelated boilerplate and paste only the 15–40 lines surrounding the failure.
  • Your Current Hypothesis: Write one sentence explaining what you already checked and why you think it is failing.
Prompt · Root-Cause Debugging (No Blind Rewrites) 
Language/Environment: Python 3.12 (standard library only, no third-party packages).
Goal: Return the shortest path length in an unweighted graph using BFS.

Expected output for input edges [(0,1), (1,2), (0,2)] from 0 to 2: 1
Actual output: 2

Minimal code:
[Paste only the bfs() function here]

My hypothesis: I think I am marking nodes visited after popping instead of when enqueuing, or overwriting the distance dictionary.

Do NOT rewrite the whole function yet. First, trace my code line by line on the failing input and show the exact state of the queue at each step.

Socratic Prompting for Course Assignments

Many university honor codes permit conceptual hints and syntax explanations while forbidding generated assignment solutions. A Socratic prompt explicitly instructs the model to withhold finished code and guide you toward discovering the flaw yourself. This mirrors office hours and builds the diagnostic intuition you need for technical interviews.

Prompt · Socratic TA Mode for CS Homework 
Act as a computer science teaching assistant. I am working on a binary search tree deletion method in Java.
Rules:
1. Do NOT write replacement code or give me the full solution.
2. Identify the logical edge case my current code misses (for example, deleting a node with two children).
3. Ask me 2 guiding questions that help me figure out how to update the parent pointer safely.

Generating Edge-Case Tests Before Submission

Autograders rarely fail students on the happy path; they fail on empty arrays, single-element lists, duplicate keys, negative integers, and integer overflow. Once your implementation passes sample tests, ask your AI assistant to act as an adversarial QA engineer and propose edge cases you have not tested yet.

Prompt · Adversarial Unit Test Generator 
Here is the specification for my assignment function: [paste prompt/spec].
Here is my function signature: def parse_intervals(raw: list[str]) -> list[tuple[int, int]]

Write 8 concise pytest unit tests covering boundary and malformed inputs (empty input, overlapping intervals, unsorted ranges, single-point intervals, negative bounds). Explain briefly what bug each test catches.

Never Skip the Diff Review

Whether you use GitHub Copilot inside VS Code or a web chat window, always inspect git diff before committing. Catching a silently deleted edge-case guard takes ten seconds in a diff view and saves hours of confusion before the lab deadline.
